Guided CacheManager Test

Goal: test the page-allocation boundary where scheduler request state becomes engine-readable page-table entries.

The Win

This lesson adds tests/core/test_cache_manager_allocate_paged.py. The tests cover CacheManager.allocate_paged without a running model server.

Primary sources: scheduler/cache.py, core.py, and the CacheManager test pattern.

The Invariant

The scheduler should allocate fresh physical KV-cache pages only for pages intersecting the uncached request region. Cached prefix entries already in the page table must stay untouched. 

first_page = ceil(cached_len / page_size)
last_page = ceil(device_len / page_size)

The allocation range is [first_page, last_page). For page_size = 4, cached_len = 4, and device_len = 10, the manager allocates two pages: logical pages 1 and 2.

The Test Setup

The test uses type="naive" because it is testing physical page allocation, not radix prefix matching. That keeps the seam small: 

page_table = torch.full((1, 16), -1, dtype=torch.int32)
manager = CacheManager(
    num_pages=8,
    page_size=4,
    page_table=page_table,
    type="naive",
)

Preserve Cached Prefix

The first test preloads the cached prefix area with sentinel values: 

page_table[0, :4] = torch.tensor([100, 101, 102, 103])

After allocate_paged, those values must still be present. If a future change overwrites cached prefix entries, this test catches it before a full server run.

Write Uncached Pages

With cached_len = 4 and device_len = 10, the test expects token-level physical locations in positions 4 through 11: 

assert page_table[0, 4:12].tolist() == list(range(8))
assert torch.all(page_table[0, 12:] == -1)

This verifies both sides of the boundary: the uncached page range is written, and unrelated positions remain untouched.

Track Free Slots

The same example consumes two pages. With eight pages total, six page starts should remain: 

assert manager.free_slots.tolist() == [8, 12, 16, 20, 24, 28]

This makes the allocation count explicit. It also checks page alignment, which is critical when page_size > 1.

How To Run It

Once the Python environment is installed, run: 

python -m pytest tests/core/test_cache_manager_allocate_paged.py -q

If dev plugins are missing, use: 

python -m pytest -q -o addopts='' tests/core/test_cache_manager_allocate_paged.py

For dated local verification blockers, see NOTES.md.

Retrieval Check 1

Why does this test use type="naive" instead of type="radix"?

Because the invariant is physical page allocation, not prefix-tree matching. The naive cache keeps the test focused on allocate_paged.

Retrieval Check 2

With page_size = 4, cached_len = 4, and device_len = 10, how many pages are allocated?

Two pages. ceil(4 / 4) = 1 and ceil(10 / 4) = 3, so the half-open page range has 3 - 1 = 2 pages.

Source Exercise

Open test_cache_manager_allocate_paged.py and trace test_allocate_paged_writes_only_uncached_pages into cache.py. Find where logical page numbers become token-level physical locations.

allocate_paged calls _allocate to get page starts, then _page_to_token expands each page start into token-level locations before _write_page_table writes them into the page table.

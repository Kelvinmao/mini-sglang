Run and Debug Startup

Goal: learn the startup path well enough to diagnose whether a failure belongs to the environment, model loading, process wiring, scheduler, engine, or frontend.

The Win

Before changing scheduler or KV-cache logic, you need a reliable way to start the system and classify failures. This lesson gives you that runbook.

Primary sources: README.md, server/args.py, server/launch.py, and the run/debug checklist.

First Principle

Mini-SGLang is not a single Python function call. Startup has layers: Python environment, CUDA visibility, dependency import, model config, model weights, process launch, ZMQ wiring, scheduler initialization, engine initialization, and frontend serving.

If an earlier layer is broken, later layers may look suspicious but are not the right place to debug yet.

Preflight Commands

Run these before launching the server: 

python --version
uv --version
nvidia-smi
python -c 'import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.device_count())'

On this workspace at lesson creation time, Python and uv were present, but the active interpreter did not have torch installed and nvidia-smi reported OS-blocked GPU access. That means a real server launch would currently fail before scheduler logic becomes relevant.

Install Path

The repo's normal editable install path is: 

uv venv --python=3.12
source .venv/bin/activate
uv pip install -e .

Read pyproject.toml when install fails. This project depends on CUDA-facing packages such as PyTorch, FlashInfer, SGL kernels, TVM FFI, and related runtime packages.

Minimal Launch

The main entrypoint is __main__.py, which calls launch_server(). The basic launch command is: 

python -m minisgl --model "Qwen/Qwen3-0.6B"

server/args.py parses --model, --tp-size, --cache-type, --page-size, --attn, --host, and --port. Defaults include host 127.0.0.1, port 1919, tensor parallel size 1, and cache type radix.

What Should Start

server/launch.py starts backend processes before the API server declares itself ready.

  1. One scheduler process for each tensor-parallel rank.
  2. One detokenizer worker.
  3. --num-tokenizer tokenizer workers, or a shared tokenizer/detokenizer worker when the count is zero.
  4. The frontend FastAPI/Uvicorn server.

The launcher waits for acknowledgements from the primary scheduler, tokenizers, and detokenizer. If you do not see readiness logs, classify the failure before sending HTTP requests.

Classify Failures By Layer

Import failure

Missing package or incompatible install. Check active venv, pyproject.toml, and whether CUDA packages installed.

CUDA failure

nvidia-smi fails, CUDA unavailable in PyTorch, or kernels cannot initialize. Fix runtime visibility before scheduler work.

Model failure

Bad model path, download problem, unsupported config, dtype issue, or weight-loading failure. Check utils/hf.py and engine/config.py.

Process failure

Missing readiness acknowledgement from scheduler/tokenizer/detokenizer. Check server/launch.py and process-specific logs.

Scheduler failure

Requests arrive but do not make progress through prefill/decode. Check scheduler/scheduler.py, prefill.py, decode.py, and cache.py.

Frontend failure

Server is up but requests fail. Check route shape in server/api_server.py, port, host, streaming, and abort handling.

Useful Debug Knobs

These come from server/args.py and env.py.

--dummy-weight

Skip real model weights, useful for startup-path testing.

--cache-type naive

Disable radix prefix reuse to isolate radix-cache behavior.

--cuda-graph-max-bs 0

Disable CUDA graph capture while debugging execution issues.

MINISGL_DISABLE_OVERLAP_SCHEDULING=1

Use the non-overlapped scheduler loop for simpler control flow.

LOG_LEVEL=DEBUG

Increase log detail through the shared logger.

LOG_PID=1

Add process ids to logs when many workers are active.

Request Smoke Test

Once the server is ready, test the simple endpoint first: 

curl -N http://127.0.0.1:1919/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Say hello in one sentence.","max_tokens":16}'

If this works, then test the OpenAI-compatible route: 

curl -N http://127.0.0.1:1919/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"Qwen/Qwen3-0.6B","messages":[{"role":"user","content":"Say hello."}],"max_tokens":16,"stream":true}'

Retrieval Check 1

If python -c 'import torch' fails, should you inspect PrefillManager first?

No. That is an environment/import failure. Fix the active Python environment before debugging scheduler behavior.

Retrieval Check 2

Which file tells you how many scheduler, tokenizer, and detokenizer processes should launch?

python/minisgl/server/launch.py. It starts one scheduler per TP rank, one detokenizer, and the configured tokenizer workers.

Source Exercise

Open scheduler.py. Find the branch that chooses between normal_loop and overlap_loop. Then open env.py and find the environment variable that controls it.

Scheduler.run_forever checks ENV.DISABLE_OVERLAP_SCHEDULING. The environment variable name is MINISGL_DISABLE_OVERLAP_SCHEDULING.

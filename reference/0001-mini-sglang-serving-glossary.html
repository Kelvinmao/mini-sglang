Mini-SGLang Serving Glossary

A compact reference for the words that matter when tracing and changing scheduler or KV-cache behavior.

Request

One user generation job. In code, scheduler-side request state is Req in core.py.

Prefill

The phase that processes prompt tokens and writes their K/V tensors into cache. In this repo, prefill admission and chunking live in scheduler/prefill.py.

Decode

The repeated phase that generates one new token per running request per forward pass. The decode set lives in scheduler/decode.py.

Batch

A scheduled group of requests for one model forward. In code, Batch.phase is either prefill or decode.

KV Cache

GPU memory holding key/value tensors from earlier tokens so later attention does not recompute them. Physical storage is owned by the engine; allocation and reuse are coordinated by the scheduler cache manager.

Page Table

A GPU table mapping request token positions to physical KV-cache token slots. The engine creates it, and scheduler/cache.py writes into it.

Prefix Cache

A logical index over cached token prefixes. With radix cache enabled, matching prompts can reuse already-computed KV slots.

Radix Cache

A compressed prefix tree for sharing KV-cache pages across requests. Its implementation is kvcache/radix_cache.py.

Scheduler

The process that decides what work runs next. It receives tokenized requests, chooses prefill or decode batches, prepares page tables, calls the engine, and streams sampled tokens onward.

Engine

The per-GPU executor. It owns model weights, attention backend, KV tensors, sampling, CUDA stream, and optional CUDA graph replay.

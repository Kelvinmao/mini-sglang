Scheduler & KV-Cache Visualizer Map

How the trace is produced, what one step contains, and where to look when the animation and the code disagree.

Pipeline

  1. An env-gated tracer records one snapshot per scheduler iteration to a JSON file: trace/tracer.py.
  2. A curated offline driver produces a legible trace: benchmark/offline/trace_radix_demo.py.
  3. A self-contained HTML viewer replays it: visualizer/index.html.

Hook Points

Batch composition

Snapshotted before the forward pass in scheduler/scheduler.py (normal_loop).

match / insert / evict

Emitted from kvcache/radix_cache.py.

alloc

Emitted from allocate_paged in scheduler/cache.py.

Tree snapshot

dump_tree on the radix cache serializes node uuid/length/ref_count/protected.

One Step (hybrid record)

{
  "index", "phase", "description",
  "batch":  [{ uid, phase, cached_len, device_len, extend_len }],
  "tree":   [{ uuid, parent, length, ref_count, protected, tokens }],
  "evictable_size", "protected_size", "used_pages", "free_pages",
  "num_pages", "page_size",
  "events": [{ kind: match|insert|evict|alloc, ... }]
}

The snapshot is authoritative state; the events are what changed. The viewer draws the snapshot and highlights the events.

Required Knobs

MINISGL_TRACE_SCHEDULER_PATH

Non-empty output path enables tracing; empty disables it (no overhead).

MINISGL_DISABLE_OVERLAP_SCHEDULING=1

Required. Tracing hooks live in normal_loop, so each step is one clean schedule → forward → commit unit.

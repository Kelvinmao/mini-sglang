Radix Prefix Cache Reference

The minimum map for reading or modifying kvcache/radix_cache.py.

Objects

RadixTreeNode

One compressed edge. _key stores token ids, and _value stores the matching physical KV-cache token locations.

RadixCacheHandle

A stable pointer to a matched node plus cached_len. Scheduler code locks a handle before using its physical indices.

RadixPrefixCache

The cache index. It owns the tree shape, reference counts, protected/evictable accounting, prefix matching, insertion, and eviction.

fast_compare_key

C++ helper exposed through kernel/radix.py. It finds the first different token in two CPU tensors.

Operations

  1. match_prefix(input_ids): walk the tree and return the longest page-aligned cached prefix.
  2. lock_handle(handle): protect the matched path so eviction cannot remove it while a request uses it.
  3. insert_prefix(input_ids, indices): add newly computed page-aligned prefix tokens and their physical KV locations.
  4. evict(size): remove old unprotected leaf nodes until at least size token slots are freed.

Invariants

  1. len(node._key) == len(node._value).
  2. Non-root nodes represent edge segments, not full prefixes.
  3. A full matched prefix is reconstructed by walking from node to root.
  4. Matches and inserts are aligned down to page_size.
  5. Only nodes with ref_count == 0 are evictable.
  6. Eviction removes leaves, because removing an internal node would orphan children.

Scheduler Connection

scheduler/cache.py calls match_prefix before prefill admission and insert_prefix after prefill/decode work makes a prefix cacheable. It also calls evict when fresh pages are needed and free pages are exhausted.

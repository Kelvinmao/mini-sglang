Mac Mini Adaptation Map

What must change to make Mini-SGLang run on Apple Silicon.

Current Answer

The current Mini-SGLang server in this repo does not run as-is on a Mac Mini. The repo README says Mini-SGLang supports Linux only and depends on CUDA-facing kernel packages.

Blockers

Engine device

engine.py hardcodes cuda:{rank}, CUDA streams, CUDA events, and CUDA memory APIs.

Graph runner

engine/graph.py is built around CUDA graph capture and replay.

Attention backends

attention/fa.py, attention/fi.py, and attention/trtllm.py use CUDA-oriented kernels.

KV store kernel

kvcache/mha_pool.py stores K/V rows through minisgl.kernel.store_cache, which is a CUDA JIT wrapper.

Sampling and fused ops

engine/sample.py and several layers call FlashInfer for sampling, activation, norm, and RoPE operations.

Tensor parallelism

distributed/impl.py and kernel/pynccl.py are NCCL/PyNCCL-oriented for GPU collectives.

Pragmatic Port Target

  1. Single process or one scheduler rank only.
  2. No tensor parallelism.
  3. No CUDA graph replay.
  4. No FlashInfer, TensorRT-LLM, or SGL CUDA attention backend.
  5. Use PyTorch mps when available; allow CPU fallback.
  6. Use simple PyTorch attention first, then optimize later.

Porting Order

  1. Add a device abstraction: cuda, mps, or cpu.
  2. Add a no-graph runner for non-CUDA devices.
  3. Add a PyTorch attention backend.
  4. Add a PyTorch KV-cache store path.
  5. Add PyTorch sampling fallbacks.
  6. Disable tensor parallelism on Mac.
  7. Make dependencies optional by platform.
  8. Run tiny-model smoke tests.

Scheduler and Cache Change Workflow

A checklist for modifying scheduler or KV-cache logic without needing a full GPU server run for every edit.

The Loop

  1. Name the behavior you want to change.
  2. Find the smallest owner file.
  3. Write the invariant in one sentence.
  4. Pick the cheapest test seam.
  5. Write the failing test.
  6. Make the smallest code change.
  7. Run the targeted test.
  8. Only then run broader GPU/server validation.

Cheap Test Seams

Decode policy

Test DecodeManager directly. It only needs lightweight Req objects.

Table slots

Test TableManager with CPU tensors and simple allocate/free assertions.

Page allocation

Follow test_cache_allocate.py. It creates a CPU CacheManager and checks page alignment.

Radix behavior

Test RadixPrefixCache through CacheManager.prefix_cache with CPU token tensors.

Invariant Examples

  1. Decode batches are emitted in stable request-id order.
  2. Finished requests never remain in running_reqs.
  3. free_slots always contains page starts, not arbitrary token ids.
  4. Eviction never returns overlapping page ranges.
  5. Prefix-cache matches never reuse partial pages.

Test Command Shape

python -m pytest tests/core/test_cache_allocate.py -q

Run the narrowest relevant test first. Use full server validation only after the local invariant passes.

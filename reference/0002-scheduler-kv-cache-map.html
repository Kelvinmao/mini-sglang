Scheduler and KV Cache Map

A quick reference for changing prefill admission, decode batching, prefix reuse, or KV-page allocation.

Where To Edit

New request admission

Edit scheduler/prefill.py. Start at PrefillManager.schedule_next_batch and PrefillAdder.try_add_one.

Decode batch policy

Edit scheduler/decode.py. Start at DecodeManager.schedule_next_batch.

Prefill vs decode priority

Edit scheduler/scheduler.py. Start at _schedule_next_batch.

Physical KV-page allocation

Edit scheduler/cache.py. Start at CacheManager.allocate_paged, _allocate, and _page_to_token.

Logical prefix reuse

Edit kvcache/radix_cache.py. Start at match_prefix, insert_prefix, and evict.

Request length invariants

Edit carefully in core.py. Req.cached_len, Req.device_len, and Req.extend_len drive scheduling and allocation.

Core Invariants

  1. cached_len tokens already have valid KV-cache locations.
  2. device_len tokens are represented in scheduler device tables.
  3. extend_len = device_len - cached_len is the next forward region.
  4. Fresh page allocation is only needed for pages intersecting [cached_len, device_len).
  5. The radix cache indexes logical token prefixes but stores physical KV-cache token indices.
  6. Page starts in free_slots must remain aligned to page_size.

Tests To Read First

tests/core/test_cache_allocate.py is the best existing test file for the cache allocator. It covers eviction, page alignment, and page-to-token expansion when page_size > 1.
